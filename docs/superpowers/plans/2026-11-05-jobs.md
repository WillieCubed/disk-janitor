# Deterministic Local Jobs Implementation Plan

> For agentic workers: use inline execution and one independent whole-change review. User explicitly opted out of design questions and requested installation and end-to-end verification.

Goal: agents submit commands; deterministic machinery owns scheduling, lifecycle and recovery.
Architecture: preserve the existing guard as admission authority, add durable job records and permission-preserving workers, and keep legacy callers compatible.
Tech stack: Python standard library, existing Bash guard and OS file locks. Java/TLC are verification-only dependencies.
Spec: ../specs/2026-11-05-jobs-design.md

## Global constraints
- No destructive expansion beyond inactive Cargo incremental, Gradle build cache and Xcode DerivedData.
- No arbitrary command replay, sandbox/approval bypass, manual path inventories or policy flags in normal submissions.
- Keep reserves and actual mount identity, retain user artifacts, and preserve existing dirty source and running jobs.

## Review focus
Fresh submission identity; lost worker/guardian result; cancellation before launch; concurrent cleanup and cache users; starvation under mixed workloads; RunnerPools/nested ownership; missing output mounts; log bounds and consumer visibility.
