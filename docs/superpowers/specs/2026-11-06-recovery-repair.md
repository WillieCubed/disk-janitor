# Recovery repair

Agents continue submitting and observing jobs through the existing public API. Repair the existing recovery implementation; introduce no new broker, daemon or agent policy controls. Actual executed programs and Java entrypoints determine compiler activity. Arguments of queued guardians and ordinary Python/shell tools do not prove compiler activity. Open-file inspection and inspection failure remain conservative.

Discover inactive Cargo incremental units, positively identified generated Cargo dependency object/archive/metadata files, marked Gradle transform build-cache entries, existing Gradle task cache and standard Xcode DerivedData. Preserve source, credentials, databases, symlinks/foreign ownership, unique outputs and active resources. New cache discovery must require canonical category structure and format/provenance checks; filename alone is not permission to delete an arbitrary file. Do not add dependency downloads, images, containers, volumes or worktrees.

Retain recovery/admission/execution fences and bounded natural-drain protocol. Validate independently recoverable units so protected content does not poison unrelated units. Batch validation and native removal with bounded activity/pressure checkpoints; revalidate identities after fresh activity inspection. Pressure recovery stops when measured capacity fits the oldest waiter plus active commitments; never reclaim merely for a sum of queued estimates. No arbitrary process interruption or replay.

Reports distinguish estimated allocated bytes from actual filesystem free-space change. Safety assumes cooperative guarded writers and does not claim an OS sandbox against malicious same-user mutation. Formal properties and assumptions remain explicit.

Historical failed jobs are audited read-only, without rerun/cancellation or claims that a related later success establishes all external work completed.
